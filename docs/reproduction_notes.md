# Reproduction notes

This is an implementation of the original IterCOMP algorithm, not a claim of matching the paper's numerical results. Local validation used synthetic samples and mocked models only. No checkpoint weights were downloaded, no pretrained models were loaded, and no MuSiQue inference, calibration or evaluation experiment was executed.

## Source and confirmed settings

The locally supplied **IterCOMP: Reasoning-aware Adaptive Prompt Compression for Multi-hop Question Answering**, JungMin Yun and YoungBin Kim, was read in Sections 4–5 and Appendix A (Table 7). [ACL paper record](https://aclanthology.org/2026.acl-long.1559/).

| Setting | Paper / requested original behavior | Implementation |
| --- | --- | --- |
| Evidence units | Sentence-level, Section 4.2.1 | Independent non-overlapping sentences |
| Encoder | Frozen pretrained BGE-M3, Section 4.2.2 | `BAAI/bge-m3`, genuine dense and learned sparse heads |
| Semantic score | Equation 1 | Dense inner product, no extra normalization |
| Lexical score | Equation 3 | Sparse token-ID weighted inner product |
| Combined score | Equation 4 | `0.6 * semantic + 0.4 * lexical` |
| MuSiQue filter | Equation 5, Section 5.1 | 90th percentile over the full original candidate pool, `>=` including ties |
| Controller | Sufficiency of original question; Table 7 prompt | Same question and current accumulated evidence every iteration |
| Follow-up | One missing-information question | Score that question alone against the same original pool |
| Accumulation | Progressive accumulation, Section 4.2.3 | Stable-ID monotonic union |
| Stop | Answerable or maximum of 5 iterations | Initial filtering pass is iteration 1 |
| Reader family | LLaMA-3-8B, Section 5.1 | Configurable Llama reader, instruction variant chosen below |

## Underspecified choices and explicit adaptations

* **Checkpoint variants.** Default reader is `meta-llama/Meta-Llama-3-8B-Instruct`; default controller is `mistralai/Mistral-7B-Instruct-v0.3`. The paper's main controller checkpoint and exact reader variant are not established by the inspected text. Mistral is motivated by the preliminary answerability experiment, not asserted to be its exact main-experiment controller.
* **Quantization and generation.** Both generative models use NF4, double quantization, FP16 compute, SDPA attention and deterministic greedy decoding. Controller output limit is 256; reader limit is 64; encoder batch size is 16 and max length is 8192. These are cloud execution choices, not paper-reported settings. The seed is 42. Quantization can affect outputs.
* **Revisions.** Profiles leave revisions unpinned to allow initial access. Pin model and tokenizer revisions to immutable Hub commit hashes for research runs. The backends record resolved model revisions when available. Attached local checkpoints should be immutable, versioned datasets; their paths alone do not establish a weight checksum. Record their source commits/checksums with the experiment. Backend and package versions are recorded. Defaults do not imply a GPU-verified dependency stack.
* **Sentence segmentation.** `spacy.blank('en')` plus its rule-based sentencizer requires no pretrained sentence model. It uses tokenizer abbreviation exceptions, preserves exact sentence substrings and character offsets, and skips whitespace-only spans. Sentence-adjacent whitespace may belong to the inter-sentence gap, not a sentence; internal whitespace is unchanged. Ambiguous abbreviations and quotations remain rule-based segmentation limitations. The exact splitter is not specified in the paper. No regex fallback, overlapping windows, merging, coreference repair or summaries are used.
* **Titles.** Titles remain metadata. Sentence-body scoring and body-only context rendering are default assumptions. Encoder title inclusion and context title inclusion are independently configurable and included in compression identity. A title experiment is a separate named setting.
* **Percentiles and ordering.** NumPy `percentile(..., method='linear')` on float64 score values; no score normalization. Rankings use descending dual score and source-order tie breaking. Retrieval lists preserve ranking order; the accumulated context follows the input paragraph order and sentence order. The paper does not specify final rendering order/interpolation. Ties can select far more than 10% of sentences.
* **Controller prompt.** The external template under `src/itercomp/prompts/controller.txt` preserves the lower Table 7 task. It corrects the printed “of if” typo to “or if”, fixes the informal bracket notation to a JSON object, explicitly requires a null follow-up for answerable, and appends labeled question/information slots. JSON fences are accepted; extra fields, duplicate keys, invalid labels, malformed JSON, and missing follow-ups are rejected.
* **Unused follow-up normalization.** The first real 30-sample smoke run exposed three valid JSON replies with an explicit `answerable` label and a string follow-up. The prior null-only check aborted those samples before reading. The pipeline now explicitly defaults to `itercomp.answerable_follow_up_policy: normalize_unused`: retain the model's label, replace only that unused string with null, and record `unused_follow_up_ignored_for_answerable` in the call and iteration trace. Raw responses, token usage and call counts are preserved. No extra generation call is made, and the follow-up never enters retrieval. `strict` reproduces the previous rejection policy; standalone `parse_judgment()` remains strict unless a policy is passed. This is an output-handling decision, not evidence that the controller judged sufficiency correctly. Invalid labels, non-string/non-null follow-ups, missing fields, malformed JSON, and unanswerable decisions without a question still fail. See [the captured-error analysis](smoke_error_analysis.md). The prompt, scoring, accumulation and stopping rules were not changed.
* **Retries.** Default zero. A configured retry repeats the same controller request after a parse failure; there is no hidden repair prompt or unbounded retry. Every returned response and attempted generation/request failure is logged. Infrastructure failures are not automatically retried. Repeated questions or no new evidence never cause early stopping.
* **Reader prompt and abstention.** The external reader template asks for a concise answer grounded only in information and the literal sentinel `INSUFFICIENT_INFORMATION` when insufficient. The prompt and sentinel are assumptions. An exact sentinel or an empty response produces an empty predicted answer and `predicted_answerable=false`; any other nonempty answer yields true. This task answerability field is independent of the final controller sufficiency judgment. The unmodified response is saved. Supporting paragraph predictions come from provenance, not reader-generated citations.
* **Empty evidence and context limits.** An empty sentence pool is an explicit sample error. Oversized controller/reader prompts fail rather than truncate. The original algorithm has no added token budget or pruning. API servers must reject oversized requests rather than silently truncate; provider-side behavior cannot be proven by the client.

## BGE-M3 adapter details

The implementation uses official FlagEmbedding `BGEM3FlagModel` and its M3 inference model. Its dense output is normalized by FlagEmbedding when `normalize_embeddings=true` (the official default); we apply the paper's dot product directly to that output. No additional vector or score normalization is applied. Sparse token weights use the official positive-weight, maximum-per-token-ID extraction, excluding CLS/EOS/PAD/UNK. The lexical score is the directly implemented weighted sparse inner product, equivalent to the official matching function. ColBERT scoring is disabled.

The pinned FlagEmbedding 1.3.5 convenience `encode()` contains a batch-size retry loop. Our thin adapter calls its official inference model directly once per configured batch, preserving dense/sparse computation while making inference calls/failures explicit. It never substitutes TF-IDF, BM25, or keyword overlap. The adapter verifies the official sparse head exists to prevent random sparse-head initialization. It also requires the complete companion head files expected by the official loader.

Input length is checked with the actual BGE tokenizer before encoding. Default `truncation_policy=error` fails the sample and records the offending length. Explicit `log` permits model-input truncation and records affected segment/query IDs and before/after lengths; it leaves the source sentence catalog intact. Such a run must disclose truncation. Sentence representations are cached within the sample only and reused across all passes. Query representations are computed every pass, including repeated queries. Embedding forward calls are separate from LLM generation calls.

Reference implementations: [BGE-M3 model card](https://huggingface.co/BAAI/bge-m3), [FlagEmbedding 1.3.5 M3 inference source](https://github.com/FlagOpen/FlagEmbedding/blob/v1.3.5/FlagEmbedding/inference/embedder/encoder_only/m3.py), [official loader and head handling](https://github.com/FlagOpen/FlagEmbedding/blob/v1.3.5/FlagEmbedding/finetune/embedder/encoder_only/m3/runner.py).

## Profiles and GPU memory

Profile names are **reader then controller**. All four retain identical BGE-M3, lambda, percentile, iteration budget and algorithm:

| File | Reader | Controller |
| --- | --- | --- |
| `itercomp_llama_mistral.yaml` | Llama-3-8B-Instruct | Mistral-7B-Instruct-v0.3 |
| `itercomp_qwen_mistral.yaml` | Qwen3-4B-Instruct-2507 | Mistral-7B-Instruct-v0.3 |
| `itercomp_llama_qwen.yaml` | Llama-3-8B-Instruct | Qwen3-4B-Instruct-2507 |
| `itercomp_qwen_qwen.yaml` | Qwen3-4B-Instruct-2507 | Qwen3-4B-Instruct-2507 |

Qwen profiles are model adaptations. The [official Qwen model card](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507) describes this instruction checkpoint's non-thinking interface; no model-specific reasoning enhancement or extra thinking switch is added. Transformers' own checkpoint chat templates are used, with no universal system-role assumption.

Default target is one NVIDIA T4 with approximately 16 GB VRAM, using FP16 rather than unsupported T4 BF16. Actual capacity depends on context lengths, KV cache, framework versions and allocator state, and has not been GPU-validated. Compression loads BGE-M3 and the controller; the reader stage loads only its reader. Each stage explicitly releases model references, collects garbage, empties unused CUDA allocator memory, and records memory snapshots. Notebooks run stages as separate processes for complete process-level release. Dual-T4 placement is explicit (`embedding.device=cuda:1`, `controller.device=cuda:0`); memory is not pooled.

NF4, optional double quantization, INT8, unquantized FP16/BF16/FP32 are supported through `BitsAndBytesConfig` and explicit settings. CPU is a configurable implementation path requiring unquantized FP32; **it must not be used for this task's real-model local execution**. There is no OOM fallback or automatic algorithm/precision/device change. SDPA is default; FlashAttention-2 is optional and rejected on T4. See [Transformers quantization documentation](https://huggingface.co/docs/transformers/v4.51.3/en/quantization/bitsandbytes).

The initial intended cloud stack was Linux/Python 3.10–3.12 with existing CUDA PyTorch 2.6.x/2.7.x. The user's later Kaggle log reports Python 3.13, PyTorch 2.11.0+cu130 and two T4s. Requirements retain the platform torch, Transformers 4.51.3, Accelerate 1.6.0, FlagEmbedding 1.3.5, sentence-transformers 4.1.0 and PEFT 0.15.2. The bitsandbytes pin was updated from 0.45.5 to 0.49.2 for its documented CUDA 13 builds. The Protobuf upper bound was removed after it downgraded the platform runtime and broke TensorFlow imports. Transformers is explicitly configured for PyTorch only before lazy imports. See the README's Kaggle repair instructions. CPU test requirements allow NumPy 1.26–2.x, spaCy 3.8.x and PyYAML 6.x. **The complete inference combination is not GPU-verified.** Do not blindly replace the platform's CUDA torch. Runtime differences and potentially incompatible preinstalled extras (such as torchvision) still require cloud validation. Local CPU tests were run on Python 3.14; that does not establish GPU-library support on 3.14.

## Tokens, latency and failures

`raw_context_tokens` and `compressed_context_tokens` use the **same selected reader tokenizer**, no special tokens, instruction or question overhead, and the exact stored contexts. They are recomputed for each reader, as are per-iteration `context_tokens`. Whole paragraphs and retained sentences use the same separator/title policy; segmentation whitespace differences are part of the measured rendering. Controller-context counts logged during compression use its tokenizer and are named `controller_context_tokens` to avoid conflating the two. An optional fixed reference tokenizer supplies additional cross-reader counts and its identity.

Generation input usage includes model chat templates. Output usage counts actually generated IDs (including stop IDs for local Transformers), not re-tokenized response text. API usage comes from the provider; missing counts stay null. API context-only counts are unknown unless `tokenizer_id` is explicitly configured to match the serving model. No-call stages have zero usage. Failed attempted generation has unknown output usage, not zero. HTTP call counts describe attempted requests; a network failure cannot prove how much computation reached the remote server. Mock counts use an explicit synthetic UTF-8 byte tokenizer and cannot be compared to pretrained token metrics.

`compression_seconds` covers the full compression algorithm including decomposition, evidence/query encoding, filtering, accumulation, prompt rendering, controller calls, parsing and tracing. Stage models are initialized before the per-sample timer; no warmup is performed. GPU calls synchronize before/after timed inference. `reader_seconds` includes reader context token accounting, rendering/generation and parsing. `reader_inference_seconds` isolates backend generation time; detailed decomposition/encoding/filter/controller timings are recorded. `total_seconds = compression_seconds + reader_seconds`, preserving reused compression cost across notebook sessions. File serialization is excluded and reported separately in metadata. `model_initialization_seconds` includes `weight_loading_seconds` and tokenizer/import/setup time; those two fields are nested costs, not additive. Download time is included in weight loading if not cached. No cross-sample encoder cache is used; within-sample reuse is declared.

Initialization errors interrupt the run. Sample errors are persisted, not silently skipped; inference is not retried with altered settings. `stop_reason=max_iterations` retains the actual final false controller judgment. It still sends the final accumulated evidence to the reader. Success/failure annotations and coverage are not inferred from gold during inference. Supporting-paragraph recall remains an evidence-coverage proxy, not a sufficiency label or proof of entailment.
